# ZMONOPOLY

The full product brief is in SPECIFICATION.md. Section 130 limits the initial delivery to Milestone 1. Later user requests authorize bots, ten original human characters, removal of chat, and a Halloween visual overhaul. v0.2.0 is desktop-only and removes the commercial header. It adds custom district architecture, storm effects, city NPCs, fullscreen dice, private tactical cards, surprise choices, city events and custody with police escorts. Use five-minute normal/planning timers, ten-minute crisis recovery and early planning completion. Keep text readable. The user then authorized the remaining gameplay systems: trading/counteroffers, auctions, bank loans/refinancing and preset contracts. v0.3.0 adds those, three modes, net scoring and animation feedback. Keep unrequested influence/policy/executive systems separate. Preserve long timers even in Blitz. v0.3.1 adds funded-payment claims, a 30-round Domination cap, production build/server.mjs, precompressed browser assets and Docker/Caddy hosting. Never credit unfunded claims as spendable cash or double-count shortfalls in scoring. Browser preview fixtures must use isolated saves. v0.3.2 adds detailed illuminated facades, remote Ravenwatch Prison, instanced bats and property/navigation markers. Keep dice fullscreen only for the local manual roller; no ambient sound loop. Round one starts with movement; planning starts in round two. Normal decisions share one five-minute turn; auctions and recovery suspend that budget, and pause/restart preserve remaining time. v0.3.3 removes the sidebar branding/always-connected header; keep only small help/version controls in its footer and show connection status only on a real disconnect. v0.4.0 makes all property ownership visible on the map with labels, colored plot borders and flags; never put ownership visibility behind Settings. Keep graphics/storm/audio controls behind one small Settings button. Audio preferences and master/effects/alert levels are local to each browser, with no ambient loops; alerts must bypass effect throttling. Auction passes apply only to the current price: a new bid clears them and reopens every rival’s response. Keep bidder END/SKIP/PASS attempts rejected.

- Work in this existing checkout; cloud tasks are already isolated. Do not create a worktree unless asked.
- Node 22.12+; npm lockfile is authoritative. In this cloud machine use `npm ci --cache /workspace/.npm-cache`.
- `npm run dev`: Vite + one Fastify/Socket.IO server. `npm run build && npm start`: one production process serving both assets and sockets on port 3001.
- Run `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` for code changes. For UI changes run `npm run test:browser` and inspect screenshots in ignored artifacts/. Browser tests use system Chromium (CHROMIUM_PATH override).
- Gameplay belongs in packages/game-core, never in presentation components. Every command must be validated, server-authoritative and transactional, including RNG.
- Keep all authentication tokens and RNG state out of public socket snapshots. Never commit save/.
- Preserve the one-session, one-board, maximum-15-player design. No accounts, room codes, matchmaking, Redis, or database services.

- Display the release version from package.json, include it in health responses, and bump it with a matching Git tag for future releases. Do not confuse game-state command versions with release versions.
